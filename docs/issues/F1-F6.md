# GitHub Issue Drafts: PRD Features F1–F6

This document contains draft GitHub issues for core MVP features F1 through F6 defined in the [Moonlight Product Requirements Document](../../Moonlight%20Product%20Requirements%20Document.md). Each issue specifies feature scope, current delivery status, associated PRs, and verification details.

## Issue: [F1] Process Investigator

- **Feature**: F1. Process Investigator
- **Status**: Implemented
- **Delivered by**: PR #2, PR #3, PR #7, PR #8
- **Milestone / Track**: Core Evidence & Rule Engine

### Scope
On-demand, read-only investigation of a selected Windows process:
- Collect process metadata (executable path, parent/ancestor chain, command line, start time, user identity, network connections, and I/O counters) via `psutil`.
- Streamed SHA-256 binary hash collection with bounded file reads and timeout protection.
- Windows Authenticode digital-signature verification with explicit four-state status reporting (`signed_valid`, `signed_invalid`, `unsigned`, `unavailable`).
- Bounded immutable evidence model (`EvidenceBundle`, `EvidenceItem`) with deterministic citation IDs and explicit reasons for missing/unavailable data.
- Deterministic process rule engine evaluating transparent heuristics (e.g., unsigned binary executing from temporary folders), missing-evidence capping, and derivation explanations.
- Strict fallback to local rules-only results when offline or without model reasoning.

### Associated Pull Requests
- **PR #2** (`feat(core): evidence schema with stable IDs`): Defined evidence models, short deterministic citation IDs, and JSON schema contract.
- **PR #3** (`feat(collector): process evidence collectors`): Implemented read-only process metadata collector, executable hasher, Authenticode verification, and `moonlight collect` CLI.
- **PR #7** (`fix(core): deep-freeze and bound evidence values`): Deep-froze evidence containers and bounded serialized values to 64 KiB to prevent mutation and memory exhaustion.
- **PR #8** (`feat(rules): process rule engine`): Implemented deterministic process rule engine, YAML weights, missing-evidence handling, and `moonlight rules` CLI.

## Issue: [F2] Storage Investigator (read-only)

- **Feature**: F2. Storage Investigator (read-only)
- **Status**: Implemented
- **Delivered by**: PR #4
- **Milestone / Track**: Storage Investigator

### Scope
Read-only folder scanning and disk space analysis:
- Bounded directory scanner measuring folder sizes, file age, extension-based file types, and size-first duplicate candidate hashing without following dangerous reparse points or symbolic links.
- Transactional SQLite snapshot storage tracking folder sizes over time and calculating growth rates across comparable scans.
- Protected-location classification categorizing paths into `clearly_safe`, `review_first`, and `do_not_touch`.
- Strict override-prevention protection for Windows system directories and user document/personal folders.
- Read-only execution: no deletion, moving, or remediation actions are executed.

### Associated Pull Requests
- **PR #4** (`feat(storage): add read-only storage investigator`): Implemented storage scanner, transactional SQLite snapshot persistence, location-based safety classifier, and `moonlight storage` CLI benchmark.

## Issue: [F3] Process-to-Disk Link

- **Feature**: F3. Process-to-Disk Link
- **Status**: Implemented and live-validated
- **Delivered by**: PR #5, PR #9, PR #10
- **Milestone / Track**: Correlation & Storage Investigation

### Scope
Attributing rapid folder growth to active Windows processes:
- Deterministic correlation comparing folder growth deltas against process write-byte deltas and open-file handle queries (`open_files`).
- Four-tier attribution confidence scoring (`high`, `medium`, `low`, `unattributed`) based on open handles, byte ratios, and timing skew guards.
- P3 findings adapter linking process security rule findings to attributed disk growth by exact process identity (`PID:creation_time`) and remapping evidence citations to versioned snapshot IDs.
- CLI workflow (`moonlight disk-snapshot` and `moonlight disk-link`) supporting isolated captures and comparisons.
- Live Windows decoy validation under both held-open and closed-handle write patterns.

### Associated Pull Requests
- **PR #5** (`feat: attribute fast disk growth to selected processes`): Implemented open-file path collection, folder growth comparison, confidence derivation, and P3 findings adapter.
- **PR #9** (`feat(storage): use P3 findings in process-to-disk link`): Integrated local P3 process rule engine findings with AFTER disk snapshots and citation remapping.
- **PR #10** (`docs: validate disk-link on a real Windows machine`): Added bounded live decoy fixture and documented real Windows verification measurements in `docs/limitations.md`.

## Issue: [F4] AI Investigation Report

- **Feature**: F4. AI Investigation Report
- **Status**: Remaining
- **Delivered by**: None (planned)
- **Milestone / Track**: Reasoning Layer

### Scope
Generate schema-validated investigation reports using Meta's Model API:
- Consume privacy-minimized evidence payloads generated by the local minimizer (redacting usernames, hostnames, private path segments, and internal IPs).
- Produce structured JSON report adhering strictly to the investigation report schema:
  - Observed factual findings citing valid evidence IDs.
  - Hypotheses explaining the observed process and storage behaviors.
  - Analysis of uncertainty and missing evidence.
  - Legitimate alternative explanations (mitigating false positives).
  - Risk tier assessment with confidence scoring.
  - Constrained, safe recommended next steps.
- Strict provenance requirement: every factual claim in the report must explicitly cite stable evidence IDs.
- Local fallback: if the Meta Model API is unreachable, fails, or returns malformed output, Moonlight falls back to deterministic rules-only results.

### Blockers / Dependencies
- Requires local privacy minimizer (implemented in PR #6).
- Requires Meta Model API client configuration and response schema validation.

## Issue: [F5] Policy Layer and Consent Flow

- **Feature**: F5. Policy Layer and Consent Flow
- **Status**: Completed
- **Delivered by**: PR #11 (feat/policy-layer)
- **Milestone / Track**: Action & Safety Gate

### Scope
Deterministic local safety and authorization layer governing proposed remediation actions:
- Every proposed space-freeing or process-related action must pass strict local policy validation before presentation.
- Allowlist-only file operations: the only permitted file action is moving files to the Windows Recycle Bin via `send2trash`.
- Permanent file deletion, process termination, and registry alterations from model-reachable code paths are strictly prohibited.
- Hard safety blocks: system directories, Windows installation folders, program binaries, and user personal document folders are unconditionally blocked from any file action.
- Mandatory preview and consent flow: all actions require a dry-run preview displaying exact paths, sizes, and destinations, followed by explicit user confirmation before execution.

### Blockers / Dependencies
- Requires storage classifier labels from F2 (`clearly_safe`, `review_first`, `do_not_touch`).
- Requires action schema and dry-run execution engine.

## Issue: [F6] Review Interface

- **Feature**: F6. Review Interface
- **Status**: Remaining
- **Delivered by**: None (planned)
- **Milestone / Track**: User Interface

### Scope
Desktop graphical user interface (built with PySide6) providing transparent investigation review:
- Evidence viewer: browse collected process and storage evidence bundles with stable citation IDs.
- Report presentation: display the AI investigation report alongside rule derivation, highlighting citations linked to underlying evidence.
- Privacy inspection: show exact preview of minimized data sent to the Meta Model API and local redaction logs.
- Remediation review: interactive dry-run preview of recommended space-freeing actions with explicit user consent toggles before executing Recycle Bin operations.
- Offline/fallback indicator: clearly display when results are operating in rules-only mode due to absent or failed AI calls.

### Blockers / Dependencies
- Depends on F1, F2, F3 (implemented).
- Depends on F4 (AI Report) and F5 (Policy & Consent Flow).
